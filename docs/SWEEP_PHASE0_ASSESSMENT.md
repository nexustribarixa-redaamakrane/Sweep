## 3. Integration blockers (honest)

- **No web-capable network stack/TLS** in the current tree — cannot fetch ordinary HTTPS sites without adding a vetted stack or a KAPA-provided network service.
- **No freestanding-kernel / network-facing JS deployment** — Duktape is host-test-only and external scripts load only via an explicit local-resource provider; no kernel execution or internet fetch is claimed.
- **No graphics/windowing subsystem** beyond console/HTL primitives visible — “conventional desktop browser UI” depends on platform graphics services.
- **WOFF2** requires Brotli-based decompression; parser/decompressor not present.
- **Associated-kernel execution** not available (KDB executor seam only). Sweep services can be registered/called in management/host-test contexts; running as an isolated executing associated kernel is future work.
- **Kernel reduction** (SWEEP.md) incomplete — tree is a full OpenWindows copy; associated-kernel profile adaptation pending.

## 4. Incremental plan (buildable stages)

1. Keep existing engine/service tests green. Fix small sync issues (done: `kdb_exec.o`).
2. Add host-testable browser foundations: text modes (WEB_COMPAT/NATIVE_SU, SUCS 0xD800–0xDFFF invariant, UTF-16 surrogate boundary only in compat), browser/tab/navigation state, HTML tokenizer+basic DOM, CSS tokenizer/selector/cascade/box-model layout + paint (done), URL normalization.
3. Integrate SuperUnicode (SUTF/SUCS) through existing APIs where linkable; keep standalone fallbacks testable.
4. Define native-SuperUnicode document detection/negotiation contract (documented, deterministic).
5. Implement font pipeline scaffolding (detection, cache, SUF validation hooks) with explicit unsupported-format reporting.
6. Defer real TLS/JS/WOFF2/full rendering until dependencies are available; document blockers and provide tested interfaces.
